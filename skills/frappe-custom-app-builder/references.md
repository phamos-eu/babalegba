## bench new-app Prompt Order

Verify against frappe/utils/boilerplate.py, function _get_user_inputs, on the bench you use; the order has changed between majors.

v15:

1. App Title (default: app name in title case)
2. App Description
3. App Publisher
4. App Email (validated)
5. App License (choice list of lowercase SPDX keys fetched from the GitHub license API; offline fallback: agpl-3.0, gpl-3.0, mit, custom; default mit)
6. Create GitHub Workflow action for unittests (y/N)

v16: the six above, then

7. Branch Name (default: the branch frappe is on, for example version-16)

Non-interactive example for v16 (one answer per line, in prompt order):

```bash
cd ~/frappe-bench-v16
printf '%s\n' "My App" "Custom Frappe/ERPNext app for My Client" "phamos GmbH" "post@phamos.eu" "gpl-3.0" "n" "develop" | bench new-app my_app
```

Behavior worth knowing:

- bench new-app installs the app into the bench Python environment (editable install), builds its assets and adds it to sites/apps.txt. It does not install it on any site.
- It creates a git repository with one commit, "feat: Initialize App". Use --no-git to skip that.
- The license text is downloaded from the GitHub license API. Offline, license.txt contains "No license text found". With the key custom, license.txt contains only the word "custom".
- The MIT text from that API contains the placeholders [year] and [fullname]; bench does not fill them.
- It does not add [tool.bench.frappe-dependencies] and does not set required_apps.

## Expected Layout After Scaffolding

```text
<repo root>/
  pyproject.toml          # must be at the repository root
  README.md
  license.txt
  .gitignore .editorconfig .eslintrc .pre-commit-config.yaml
  <app_name>/             # the Python package
    __init__.py           # __version__ = "0.0.1"
    hooks.py
    modules.txt
    patches.txt
    <module_name>/        # first module, named after the app title
    config/ public/ templates/
```

If any of these are missing or in a different place, the scaffold was not generated by bench new-app. Regenerate it; do not patch it into shape.

## Hardening Snippets

pyproject.toml, after the [build-system] table:

```toml
[tool.bench.frappe-dependencies]
frappe = ">=16.0.0,<17.0.0"
erpnext = ">=16.0.0,<17.0.0"
```

The Frappe Cloud documentation shows the lower bound as ">=16.0.0-dev", which additionally accepts pre-release development builds. Either form is accepted for stable releases.

pyproject.toml [project] dependencies keep frappe and erpnext out:

```toml
dependencies = [
    # "frappe~=16.0.0" # Installed and managed by bench.
    # only real third-party packages below, for example:
    # "pandas~=2.3.3",
]
```

hooks.py:

```python
app_license = "gpl-3.0"
required_apps = ["erpnext"]
```

Validate the TOML with the bench Python:

```bash
~/frappe-bench-v16/env/bin/python -c "import tomllib; print(tomllib.load(open('pyproject.toml','rb'))['tool']['bench']['frappe-dependencies'])"
```

Fetch a license text the same way bench does (for example when changing the license later):

```bash
~/frappe-bench-v16/env/bin/python -c "from frappe.utils.boilerplate import get_license_text; open('license.txt','w').write(get_license_text('gpl-3.0'))"
```

When changing the license later, update all three places together: license.txt, app_license in hooks.py, and the License section of the README.

## Connecting to a Remote That Already Has Commits

Hosting services often create the repository with a README commit. Commit the scaffold on top of it instead of force-pushing:

```bash
cd <app_repo>
git config user.name "<Name>"
git config user.email "<work email>"
git remote add origin <repo_url>
git fetch origin
git reset --soft origin/develop
git add -A
git commit -m "feat: Initialize App"
```

The scaffold's README replaces the hosting service's placeholder README in the same commit.

## Frappe Cloud

- Custom apps can be added to private bench groups. In the bench group: Apps, Add App, connect GitHub, select organization, repository and branch, validate, add, deploy.
- The app must have pyproject.toml with [tool.bench.frappe-dependencies]. Missing table: "Could not find a compatible Frappe version in pyproject.toml".
- frappe must not be listed in [project] dependencies; bench installs it from git and pip would try to install a placeholder package instead.
- There is no native GitLab support. The common workaround is GitLab repository mirroring (Settings, Repository, Mirroring repositories) to a private GitHub repository that Frappe Cloud deploys from. Mirror at least the branch Frappe Cloud deploys.
- Users with SSH access to a private bench group can read the app's code.
